- Group 41 the question these guards answer: a guard that walks a clean tree and passes has proved the tree is clean, not that it would notice a violation. A classifier returning one layer for everything, a rule table with no forbidden edge, or a walk over a directory that no longer exists all pass exactly as loudly. That is the difference worth closing, and it is a different thing from covering every mutant of every guard.
- Group 41 layering: ADR 0004's executable form now has its classifier and its rule table under test. Every tree lands in a layer, the fallback is the strict one so a path that fell through is refused rather than exempted, each forbidden edge carries the fix guidance a contributor needs, and the scanner is driven over owned files for outward imports, inward imports, third-party imports and no imports at all. The credential guard's detector is covered the same way: the ordinary, renamed and dot-imported spellings of a mint are found, and a same-named symbol from another package, a method sharing the name, and a shadowing local are not. The provider-switch guard now fails when it scans nothing, which is how it would have passed if the app tree moved.

- Group 42 CommitPush against real Git: a dry run now has to leave the whole `.git` directory byte-identical, hashed path by path with modes, against a checkout with the untracked cache on and an uncommitted change present, with a wet control that must change it. The commit set is checked by expansion rather than by argv: a directory pathspec must produce both chart files and an unrelated dirty file must stay uncommitted. The leased path publishes the captured OID, its sole parent is the authorized source, and origin/main ends at that exact OID. When a competing writer advances origin/main first, the run refuses with the repository byte-identical, so no staged index, no author config and no commit are left behind.
- Group 42 the lease itself: `--force-with-lease` is still a force push, so the flag is only a safety if the destination honours the OID it names. That is now executed at the adapter, where a stale lease is rejected by a real bare remote and the other writer's commit survives, and a current one publishes. The positive control also pins that a later local commit the run never captured stays behind, because the refspec names an object and not a branch tip. Replacing the lease with a plain `--force`, and the captured OID with `HEAD`, were both caught.
- Group 42 the concurrency outcome, stated rather than assumed: when a foreign tag claims the release name at another commit after the bump commit is already published, TagRelease refuses, does not move or force the foreign tag, and leaves no local tag. The already-published branch commit stays published. There is no compensation and no rollback, and the test asserts that half too, so the supported outcome is written down instead of inferred from the absence of a test.
- Group 42 what native Git cannot show: a fault making TagRelease republish on every rerun did not fail the new real-repository test, because Git answers an identical tag push with "Everything up-to-date" and writes nothing.
